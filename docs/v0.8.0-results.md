# Controller v0.8.0 and CYD Meshtastic channel access

Date: 2026-11-05. This is the matched CX32L003/SX1262 radio-controller and
ESP32 CYD update. It uses the pinned Meshtastic `v2.7.26.54e0d8d` source;
it does not put a second mesh stack inside the radio controller.

## Implemented behavior

The CYD uses the unchanged upstream 16-packet priority queue and upstream
randomized/channel-utilization and SNR-weighted delay functions. Queue lookup,
cancellation, priority replacement, upgraded-hop replacement and late windows
are exposed to the upstream router. A changed queue head invalidates any
completed CAD scan. Receive activity is checked without stopping a received
frame; stale preamble flags have a bounded lifetime. After the delay the host
stops RX, runs CAD, defers on busy, and only arms/sends after a clear result.
Continuous reception resumes after completion.

GET_VERSION reports 0.8.0, capability mask 0x01FFFBFF. Command 37 explicitly
negotiates host-managed mode; command 38 reports active RX. The host-managed
mode removes the fixed 30-second MCU pause and allows up to 60 s packet airtime.
The CYD removes its corresponding 31-second rejection and 2-second packet cap.
The generic controller test policy stays conservative by default after boot.
One-shot arming, bounded packet length, sequence matching, duplicate attempt
protection, finite watchdogs and uncertain-completion recovery remain.

Configured LoRa settings, upstream/region-limited power (controller range
-9..+22 dBm), frequency slot and RX gain are forwarded. New CYD configurations
default TX off; explicitly saved TX settings survive reboot. Only the controller's
implemented 433–434 and 863–870 MHz windows are accepted.

Estimated packet TX airtime is charged once before SEND, including an uncertain
completion. Valid RX contributes once through RX_LOG; rejected raw headers use
RX_ALL_LOG. Upstream AirTime counts both types toward channel utilization, so
successful packets must not be logged to both. Actual duty/channel utilization
is checked again at queued dispatch; the ordinary regional duty override setting
retains its upstream meaning. CAD busy time is also logged as observed channel use.

## Programming and physical tests

ST-Link initially failed target access, then USB detached while the user
measured SWD. After reconnection and explicit resume, the exact MCU identity and
USERCFG guard matched. A full 64 KB pre-update Flash backup matched the preserved
v0.7.0 image prefix/hash. v0.8.0 was programmed once. All 20,476 bytes matched
host-side readback, USERCFG stayed unchanged, and reset entry/MSP checks passed.
No target-side checksum helper was used to overwrite running SRAM.

The CYD was positively identified as the known ESP32-D0WD-V3 revision 3.1.
Only its app at 0x10000 was updated; NVS, calibration and filesystem were retained.
Boot confirmed the v0.8.0 host-mode handshake, queue length 16 and TX enabled.
USB API reported EU_433, LongFast and configured 10 dBm power.

The initial pair passed a real peer sequence:

| Mesh normal 1 | 4216746718 | 9 / 10 s | TX success, implicit ACK |
| Mesh normal 2 | 85587679 | 16 / 16 s | CAD busy deferral, TX success, implicit ACK |
| Mesh normal 3 | 3130971872 | 20 / 20 s | TX success, implicit ACK |
| Normal reply (from Alr1) | 4288289865 | received 37 s, rebroadcast 42 s | received -34 dBm / 6.25 dB; user confirmed delivered |

All three submitted texts were five seconds apart; successful RF transmissions
were separated by far less than 31 seconds. The user confirmed all arrived.
The real upstream router generated matching implicit ACKs and canceled retries.
The return packet was received and rebroadcast; Alr1 confirmed delivery to mesh.
Telemetry showed nonzero TX airtime and channel utilization, rather than zero
accounting. The first test image was then intentionally revised to avoid counting
successful RX twice; no controller change was needed. Final-image verification
is recorded below.

and should not be published as raw logs.

## Limits

This is a custom, unsupported hardware variant, not a claim of complete official
board support. Public-channel EU_433/LongFast messaging, rebroadcast confirmation
and short consecutive transmissions are physically tested. Other presets,
dense-network fairness, full power cycling of this exact pair, long-run
queue stress and 868 MHz RF performance need separate qualification. Deep sleep,
GFSK as a Meshtastic mode, comprehensive failed-RX/noise-floor/counter reporting
remain unimplemented in the CYD adapter. WiFi, GPS and unused sensors remain
excluded by the established board build.

## Exact final-image verification

The final radio-stage app Flash hash verified. A fresh reset/handshake retained TX enabled,
EU_433/LongFast, 10 dBm and queue length 16. `Final mesh 1` (2627199409) and
`Final mesh 2` (2142571954) were submitted four seconds apart, transmitted at
uptime 9/13 s, completed at 10/14 s, and each received a matching implicit ACK.
`Got it` (696124282) returned from the peer at -33 dBm / 6.25 dB and was
successfully rebroadcast at uptime 32 s.

Final debug logs show 1,516 ms TX, 1,516 ms valid RX and 17 ms busy CAD. Telemetry
at uptime 45 s reported TX utilization 0.042111114% and channel utilization
5.0816665%; these match the logged sums exactly within floating-point precision.
This verifies RX is no longer counted twice and airtime is connected to the
upstream accounting used for policy decisions. The final static-RAM report is
95,280 B for the ESP32, with about 67 KB free heap reported during this short test.
There was no new panic, UART timeout, radio command rejection or watchdog event
in the final capture. This is a short test, not a long-run memory/stability proof.

Local final evidence: `cyd-upload-final.log`, `final-boot.{log,bin}`,
`final-{test,debug}.log`, `final-verification.json`, and `artifacts.json`.

A later [CYD GUI update](cyd-gui.md) also physically verified a selected-node
PKI DM to Alr1 and its matching acknowledgement. That extends the initial
