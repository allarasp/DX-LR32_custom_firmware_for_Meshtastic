# v0.5.0 configurable raw-LoRa controller: implementation and physical results

Date: 2026-11-04. Board: DX-LR32-A / CX32L003F8 / SX1262, passive 32 MHz
crystal. `meshctrl` is the retained build target name; the controller itself
has no Meshtastic packet parser, encryption or channel-slot calculation.

## Implemented

- SEND uses UART-applied LoRa SF/BW/CR/LDRO, packet format, preamble, CRC, IQ,
  sync and commanded power. The fixed LongFast/-9 dBm override is removed.
- Power remains bounded to -9..+10 dBm commanded and frequency to 433–434 MHz
  including bandwidth edges. No 868 MHz, DIO2 or DIO3 override exists.
- Actual configured modem parameters feed airtime validation. Airtime remains
  at most 2000 ms, with a one-shot arm and 30-second attempt spacing.
- GPIO release can run despite corrupt type/pull/mux configuration; cleanup
  failures invalidate configuration and are reported. GPIO faults cannot be
  reported as a valid driven switch state.
- RX read failures are reported, counters expose packet/error/timeout/cleanup
  outcomes, and finite RX expiry has an explicit event.
- The most recent SEND sequence is protected against duplicate attempts.
- UART output uses a bounded 1024-byte ISR-serviced ring, whole-frame admission,
  drop counters and stalled-transmitter cleanup. There is no heap or unlimited
  packet queue.
- BOOT and GET_VERSION use the same compile-time version: 0.5.0. Protocol version
  remains 1; existing wire formats remain unchanged.

The full contract, command IDs 21–23, duplicate status 15, new RX-timeout event,
finite-timeout semantics and remaining limitations are in
[UART_LIVE.md](UART_LIVE.md).

## Programming and boot

OpenOCD: local 0.12.0+dev-g2431daa-dirty (2026-11-03), `cx32l003` Flash driver.
Observed ST-Link firmware: V2J34S7. SWD: 100 kHz; reported Vtarget about 3.310 V.
The private known-target guard matched the recorded target and default USERCFG
words. The bank is 64 KB at zero, 128 pages of 512 B, unprotected. This is the
previously verified driver/procedure, not an STM32 substitute.

The complete pre-flash read matched the saved v0.4.0 image. Recovery artifacts
were preserved locally under `logs/v0.5.0/recovery-v040/`. There was one deliberate
programming attempt, using page erase for the image. No unlock, mass erase or
option-byte change was required. Full Flash readback matched all 12,704 bytes;
a later read after radio testing matched again.

Exact local invocations (private guard/config files and dumps stay ignored):

```sh
tools/openocd-cx32/bin/openocd \
  -s tools/openocd-cx32/share/openocd/scripts \
  -f configs/bringup-mesh-preflight.cfg
tools/openocd-cx32/bin/openocd \
  -s tools/openocd-cx32/share/openocd/scripts \
  -f configs/cx32l003-bringup.cfg \
  -c 'init; halt; flash info 0; resume; shutdown'
tools/openocd-cx32/bin/openocd \
  -s tools/openocd-cx32/share/openocd/scripts \
  -f logs/v0.5.0/program.cfg
tools/openocd-cx32/bin/openocd \
  -s tools/openocd-cx32/share/openocd/scripts \
  -f logs/v0.5.0/reset.cfg
```

The programming config sources the private identity guard, then executes
`flash write_image erase firmware/build/meshctrl/controller.bin 0 bin` and
`dump_image logs/v0.5.0/flash-readback.bin 0 12704`. Comparison was on the host;
no live target checksum helper was used. Reset halted at Reset_Handler with
MSP 0x20001000, then resumed. UART BOOT payload was `00 05 00 00` and GET_VERSION
reply `00 00 05 00 01`; the final boot byte is successful radio initialization.

## Physical UART/SX1262 regression

```sh
.venv/bin/python bin/test_live_controller.py \
  --log logs/v0.5.0/regression-final.json
```

Passed PING/PONG, capabilities 0x7BFF, rejection of 868 MHz/out-of-policy power,
three varied configuration snapshots and available sync/IQ/packet-type
readbacks, deliberate bad-CRC recovery, truncated-frame timeout/recovery,
32 consecutive PING requests/replies, finite 100 ms RX timeout, and XOSC.

Configurations included SF7/BW125000/CR4/8/implicit/CRC-off/inverted-IQ/private
sync/0 dBm; SF12/BW250000/LDRO1/private sync/+10 dBm; and public LongFast/-9 dBm.
These varied profiles were **configured without transmitting**. Successful
snapshots/readbacks do not establish RF interoperability or measured power for
all combinations. XOSC reported `0x22 -> 0x32 -> 0x22`, flags 0x00FF, zero device
errors and 18 ms. No output frames were dropped and no UART TX stalls occurred.

## Real peer exchange

A suitable 433 MHz antenna was confirmed connected. WSL CH340 UART was used;
CYD was not in this radio path. Public EU_433 LongFast, 433875000 Hz, SF11,
BW250000, CR4/5, preamble16, explicit header, CRC on, normal IQ, sync0x24B4.
The bridge explicitly supplied -9 dBm through UART.

```sh
.venv/bin/python bin/meshtastic_bridge.py listen --seconds 180 \
  --log logs/v0.5.0/discovery.json
# Stop listener with SIGINT, allowing its STOP_RX cleanup before sending:
.venv/bin/python bin/meshtastic_bridge.py send --transmit \
  --text 'Alr1: DX-LR32 v0.5.0 received you. Reply V050 OK on this channel.' \
  --seconds 180 --log logs/v0.5.0/roundtrip.json
```

1. Received `Alr1 v050 ready`: RSSI -47 dBm, SNR 6 dB.
2. One explicit packet was accepted and completed with TX_DONE. The user
   confirmed its text arrived in the phone app.
3. Received `V050 ok` from the same peer: RSSI -47 dBm, SNR 6.75 dB.
4. Also received NodeInfo from Alr1 and Ly01.
5. Replayed the exact attempted SEND frame: DUPLICATE (15), no second RF attempt.

Snapshot after the peer exchange: 8 extracted RX packets, zero CRC/header
rejects, zero RX read errors, one earlier diagnostic RX timeout, one TX attempt,
one successful TX completion, zero TX/cleanup failures, one duplicate rejection.
Transport: zero output drops, zero TX stalls, queue empty. Later regression
runs can increment the timeout counter without transmitting.

Final state: standby RC `0x22`, device errors zero, active configuration valid,
PC3/PC4 released to inputs (no pulls/mux/output latch). A final UART PING passed
after the SWD stack/Flash inspection. The listeners were stopped deliberately;
no ongoing transmission or RX session was left running.

## Remaining limits and local evidence

The user accepts factory-style RF switching for operation. No new switch
identity, rail-current, thermal, radiated-power or band measurements are
claimed. DIO2/DIO3 remain disabled. This is a verified public-channel text path,
not full Meshtastic routing/PKI/interoperability qualification. Alternate PHY
profiles, power levels and sustained/burst RF traffic still need peer tests.
There is no lossless RF queue, host-disconnect lease, general CAD/CSMA, GFSK or
persistent settings/duty budget. The host reconfigures after reboot/fault.

Local-only evidence: `logs/v0.5.0/` contains `preflight.log`, `flash-info.log`,
`program.{cfg,log}`, `reset.{cfg,log}`, `boot.json`, `regression*.{json,log}`,
`discovery.{json,log}`, `roundtrip.{json,log}`, `final-diagnostics.{json,log}`,
`final-swd.log`, `stack-result.txt`, full image/stack readbacks and build/test
logs. Raw dumps, hardware identifiers, node IDs and private session logs are
excluded from GitHub. Firmware outputs are
`firmware/build/meshctrl/controller.{elf,bin,hex,map}`.
