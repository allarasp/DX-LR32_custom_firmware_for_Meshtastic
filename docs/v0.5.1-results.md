# v0.5.1: hardware-range TX power, host-owned regional power policy

Date: 2026-11-04. Follow-up to the physically tested
[v0.5.0 controller](v0.5.0-results.md).

## Power ownership and frequency

The live CX32 controller accepts SET_TX_POWER values -9..+22 dBm, the SX1262
high-power PA command range. Regulatory power limits, antenna gain/EIRP and
application policy belong to the ESP32 or other host. The firmware rejects
values outside the silicon command range rather than imposing the earlier
+10 dBm regional ceiling. Default/test power stays -9 dBm. Power is commanded,
not measured RF output.

The live PA configuration is now 04/07/00/01 (paDutyCycle/hpMax/deviceSel/paLut),
Semtech's nominal +22 dBm SX1262 setting, rather than the earlier reduced-size
02/02/00/01 PA. SetTxParams still receives the UART-applied power, with a 200 us
ramp. The HAL whitelist enforces that exact valid PA configuration and range.
The source is the [Semtech SX1261/2 datasheet Rev. 1.2](https://files.waveshare.com/wiki/SX1262-XXXM-LoRaWAN-GNSS-HAT/DS_SX1261-2_V1.2.pdf),
sections 13.1.14/table 13-21 and 13.4.4.

Capabilities bytes 26/27 now both report 22 (hardware/controller maximum).
The historical schema field at byte 27 is no longer an EU power limit in the
live image. Wire protocol remains version 1; BOOT/GET_VERSION report 0.5.1.
The separate non-RF v0.3.1 recovery source retains its old staging limit.

Frequency is already UART-configurable in integer Hz. Its existing controller
policy remains 433–434 MHz, including configured bandwidth edges; this update
changes power policy only. The module declaration remains 433–532 MHz. Although
SX1262 silicon can tune to 868 MHz, a different antenna alone does not establish
that the assembled DX-LR32-A matching/filter/front-end network supports that
band. A future verified 868-capable board/profile can reuse the same UART
frequency encoding; 868 MHz is still rejected on this board profile. Existing
TX arm, airtime and cooldown guards remain unchanged.

## Verification

Passed:

```sh
make -C firmware -j2 check radio-check uart-check protocol-check mesh-check
.venv/bin/python firmware/tests/test_meshtastic_bridge.py
sh cyd/tests/check.sh
.venv/bin/python bin/test_live_controller.py \
  --log logs/v0.5.1/regression.json
```

The live configuration test now compiles the real config/parser/HAL path with
UART_RADIO_LIVE as well as testing the separate legacy build. Every accepted
power value (-9..22) is exercised through staging and the mocked live TX encoder;
the actual HAL guard tests that whole range and adjacent invalid values.
Out-of-range PA settings are rejected. Driver-level tests assert PA 04/07/00/01.
CYD source and host bridge accept patch 0.5.1; CYD hardware was not reflashed.

The known-target guard and a pre-program Flash comparison matched the saved
v0.5.0 image. One guarded page-erase/program attempt succeeded through the same
CX32L003 OpenOCD driver at 100 kHz. All 12,704 bytes matched direct Flash readback.
No unlock, mass erase or option-byte modification was needed. Reset halted at
Reset_Handler (0x000000c0), MSP 0x20001000, then UART BOOT was `00 05 01 00` and
GET_VERSION `00 00 05 01 01`.

Physical UART regression passed +22 dBm staging/APPLY/config snapshot and
capability reporting, rejection of +23/-10 dBm and 868 MHz, alternate modem
configuration/readbacks, CRC/truncated-frame recovery, a 32-frame PING burst,
finite RX timeout and XOSC. The max-power setting was restored to -9 dBm before
RF operation; the regression utility never arms or sends TX. Configuring +22
dBm is not proof of calibrated +22 dBm antenna output.

## Repeated real peer test

The bridge explicitly configured -9 dBm on public EU_433 LongFast at
433875000 Hz. One packet was sent:

```sh
.venv/bin/python bin/meshtastic_bridge.py send --transmit \
  --text 'Alr1: DX-LR32 v0.5.1 power-range update. Reply V051 OK.' \
  --seconds 120 --log logs/v0.5.1/roundtrip.json
```

TX_DONE succeeded. The user confirmed phone receipt, and the controller received
`V051 OK` from Alr1 at RSSI -42 dBm / SNR 5.75 dB. Alr1 and Ly01 NodeInfo were
also received. No high-power RF transmission was performed.

Final counters: 6 extracted RX packets, no CRC/header rejects/read errors,
one earlier diagnostic RX timeout, one TX attempt/completion, no TX/cleanup
failures, zero output drops/stalls. Final state: standby RC (0x22), zero device
errors, active -9 dBm configuration, PC3/PC4 released. The listener was stopped
through STOP_RX cleanup.

Size is unchanged: 12,704 B Flash, 2,392 B static RAM, 1,024 B reserved stack,
680 B remaining outside those allocations. Tool versions are unchanged from
v0.5.0. Image SHA-256:
`27ed39f93cabcf5a260c5b8c0ed7251d2cbfb486a7e7cabd409b93e5d3f32efd`.
Recovery v0.5.0 is retained under `logs/v0.5.1/recovery-v050/`; other local
programming/readback/boot/regression/peer logs are in `logs/v0.5.1/`. Generated
artifacts, raw dumps, hardware identifiers and private node logs are excluded
from GitHub. No measured power, current, thermal or 868 MHz hardware capability
is claimed by this update.
